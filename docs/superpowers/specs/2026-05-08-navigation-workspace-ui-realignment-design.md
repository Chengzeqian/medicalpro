# Navigation Workspace UI Realignment Design

**日期：** 2026-05-08  
**范围：** `medicalpro` 手术导航工作区 UI 与现有工作区聚合 / 数字孪生链路的重新对齐  
**目标：** 让准备、规划、配准、导航、评估五阶段页面只表达当前后端真实支持的能力，消除旧壳层、占位交互和误导性入口，使用户能够在软件内直接看到这轮开发后的实际效果

## 1. 背景

当前导航工作区已经完成了两类重要建设：

- 上层工作区编排能力：
  - `NavigationWorkspaceApplicationService`
  - `NavigationWorkspaceSnapshotStore`
  - `NavigationWorkspaceUiBinder`
  - `NavigationWorkflowCoordinator`
  - `NavigationRuntimeCoordinator`
- 下层实时数字孪生能力：
  - `NavigationPoseFrame`
  - `NavigationPoseStream`
  - `NavigationTransformGraph`
  - `NavigationVtkBridge`

但当前页面仍混合了三套不同阶段的实现：

1. 新工作区聚合与门禁链路
2. 旧 `NavigationPage` 四视图 / 分割 / 2D-3D / 手动导模交互
3. 明显未完成的占位入口

直接结果是：

- 用户能进入病例工作包主链
- 但进入五阶段页面后，看见的大量按钮和视图并不对应本轮 specs / plans 的真实产物
- 页面可见行为与底层真实能力脱轨，导致“开发了功能，但软件里看不到”

本次设计不再继续扩展算法，而是做一次明确的 UI 收口，把页面和底层真实能力重新对齐。

## 2. 本轮设计边界

本轮边界由用户确认如下：

- 本轮目标：`页面真实收口 + 最小可用联调`
- 模型来源规则：`严格病例工作包真源`
- 规划页形态：`中等规划页`
  - 展示规划摘要
  - 保留查看病例已绑定骨模型 / 影像的只读能力
  - 不再允许旧分割 / 旧手动导入

## 3. 目标

本轮必须达到以下结果：

1. 五阶段页面只展示当前真实可用能力
2. 所有骨模型和器械模型都只来自病例工作包绑定层
3. 页面不再保留误导性的旧导入、旧分割、旧 2D-3D 占位入口
4. 导航页可见形态从旧四视图切到单一 3D 虚拟空间
5. 用户能够在软件中直接看到：
  - 准备阶段的器械 / geometry / 标定状态
  - 规划阶段的目标骨 / 目标区域 / 约束区 / 推荐点序
  - 配准阶段的分骨结果与融合导航空间状态
  - 导航阶段的骨 STL + 当前器械 STL + 实时位姿
  - 评估阶段的病例级摘要和导出结果

## 4. 非目标

本轮不做以下事项：

- 不重写服务配准算法
- 不新增真实硬件 SDK 深度联调
- 不把规划页升级成完整交互式规划工作台
- 不保留页面内“临时导模”作为正式产品能力
- 不继续维持旧四视图导航页作为主路径
- 不在本轮恢复旧自动分割作为导航工作区主流程步骤

## 5. 方案比较

### 方案 A：最小替换

做法：

- 只隐藏或禁用明显占位按钮
- 尽量保留现有页面骨架

优点：

- 改动小
- 风险低

缺点：

- 旧导航页气味依然明显
- 用户依然会误解哪些能力真实可用
- 很难形成可联调的明确工作流

### 方案 B：阶段页真实收口

做法：

- 保留当前工作区总框架
- 逐阶段替换中间工作区内容
- 每个阶段只保留与后端真实能力一致的动作和结果
- 导航页切换为单一 3D 虚拟空间

优点：

- 与现有工作区 / 数字孪生 specs 最一致
- 能解决“软件里看不到开发效果”的核心问题
- 适合形成最小可用联调闭环

缺点：

- 需要系统性清理旧按钮、旧视图、旧路径

### 方案 C：彻底重做导航页前台

做法：

- 全量重做导航工作区 UI
- 同时替换现有页面结构和大部分控件层

优点：

- 结构最干净

缺点：

- 范围过大
- 明显超出本轮“收口”目标

### 结论

采用方案 B。

## 6. 顶层原则

### 6.1 页面只消费病例工作包真源

- 页面不允许首次导入骨模型
- 页面不允许首次导入器械模型
- 页面不允许临时写入骨模型路径作为正式流程来源
- 页面只消费：
  - `case_manifest`
  - `case_asset_bindings`
  - `planning_result`
  - `per_bone_registration_results`
  - `fused_navigation_space`
  - `navigation_run`
  - `evaluation_report`

### 6.2 页面只表达当前真实能力

- 如果某功能没有真实后端能力，不允许在主流程中保留“点击后弹提示”的假入口
- 占位入口只能删除、隐藏或移出主路径，不能继续伪装为正式按钮

### 6.3 页面不再自行维护业务真相

- 页面不再维护分散的骨路径、器械路径、规划结果、配准结果
- 页面只消费 `NavigationWorkspaceSnapshot`
- 页面中的真实动作只通过控制器进入聚合层和运行态层

### 6.4 导航页必须体现数字孪生

- 导航阶段可见结果必须是单一 3D 虚拟空间
- 不再允许旧四视图作为导航阶段主界面

## 7. 五阶段页面设计

### 7.1 准备页

定位：

- 病例工作包资产确认页
- 当前活动器械选择页
- 标定状态与标定动作页

页面展示：

- 当前病例绑定骨模型摘要
- 当前病例绑定器械摘要
- 每个器械对应的 geometry 绑定状态
- 当前活动器械
- 标定进度
- 标定精度
- 阻塞原因

允许动作：

- 选择当前活动器械
- 开始标定
- 采集标定点
- 完成标定
- 取消标定

明确移除：

- 页面内导入器械
- 页面内导入骨模型
- 临时补 geometry

数据来源：

- `asset_state`
- `calibration_state`
- `preparation_state`

### 7.2 规划页

定位：

- 中等规划页
- 展示规划摘要
- 保留只读查看病例已绑定骨模型 / 影像能力

页面展示：

- 当前活动骨
- 目标区域
- 解剖约束区
- 推荐配准点顺序
- 已绑定骨模型列表
- 影像是否存在 / 影像摘要

允许动作：

- 切换只读查看对象
- 确认当前规划摘要

明确移除：

- 自动分割
- 导出 STL
- 选择模型
- 加载模型
- 显示模型

数据来源：

- `planning_state`
- 病例工作包中的只读影像 / 模型引用信息

### 7.3 配准页

定位：

- 分骨 / 分部位配准结果页
- 点采集与计算配准页

页面展示：

- 当前活动骨
- 当前采点列表
- 分骨配准结果摘要
- 融合导航空间状态
- 当前误差指标
- 阻塞原因

允许动作：

- 采集点
- 删除点
- 清空点
- 计算配准

明确移除：

- `2D-3D 将在此实现` 这类占位入口
- 不在本轮范围内的额外配准路径

数据来源：

- `registration_state`
- `planning_state`
- `calibration_state`

### 7.4 导航页

定位：

- 单一 3D 数字孪生导航页

页面展示：

- 单一 3D 虚拟空间
- 骨 STL
- 当前器械 STL
- 实时位姿变化
- 跟踪器状态
- 配准状态
- 标定状态
- 导航准入
- 可信度
- 当前误差 / 位姿摘要

允许动作：

- 连接追踪器
- 断开追踪器
- 开始导航
- 暂停
- 重置视图

明确移除：

- `Axial / Sagittal / Coronal / 3D Volume` 四视图作为导航主界面
- 导航阶段内的旧模型加载主路径

数据来源：

- `navigation_state`
- `NavigationRuntimeCoordinator`
- `NavigationDisplayState`
- `NavigationVtkBridge`

### 7.5 评估页

定位：

- 病例级评估结果页

页面展示：

- 配准误差
- 分骨质量摘要
- `tracking_latency_ms`
- `tracking_jitter_mm`
- `visible_frame_ratio`
- 导航过程摘要
- 导出状态

允许动作：

- 导出评估报告
- 查看摘要明细

明确移除：

- 非评估性质的运行态交互

数据来源：

- `evaluation_state`
- `evaluation_report`

## 8. 页面与底层链路的对位规则

### 8.1 页面只消费统一快照

- `NavigationPage` 只从 `NavigationWorkspaceApplicationService` 获取统一工作区快照
- 页面切阶段时，不再通过局部控件状态拼业务结果

### 8.2 准备页只调准备控制器

- 准备页动作只能进入准备 / 标定控制路径
- 不允许绕过控制器直接写页面局部状态

### 8.3 规划页只读 `planning_state`

- 规划页不再直接调用旧 segmentation / four-view / 手动导模逻辑
- 所有规划展示字段必须可在 `planning_state` 中找到对应语义

### 8.4 配准页只调 `RegistrationController`

- 采点、删点、清点、计算配准统一进入 `RegistrationController`
- 配准结果统一回写到：
  - `per_bone_registration_results`
  - `fused_navigation_space`

### 8.5 导航页只消费 runtime + transform + vtk bridge

- 页面不直接计算坐标链
- 页面不直接维护变换矩阵
- 页面只负责把 `NavigationDisplayState` 交给 `NavigationVtkBridge`

### 8.6 评估页只消费评估结果

- 页面不再临时拼摘要文案作为真实评估结果
- 导出动作只调用现有评估导出路径

## 9. 旧 UI 路径处理规则

### 9.1 明确退出主流程的旧能力

以下旧路径退出主流程：

- 页面内器械导入
- 页面内骨模型手动导入
- 规划页自动分割入口
- 规划页导出 STL 入口
- 规划页加载 / 显示模型入口
- 配准页 2D-3D 占位入口
- 导航页旧四视图主界面

### 9.2 允许保留但不再暴露为主交互的旧底层代码

如果部分旧服务、旧桥接实现仍被底层复用，可以临时保留，但必须满足：

- 不再作为主流程按钮暴露
- 不再作为用户正式操作入口
- 不再和新工作区语义混用

## 10. 验收标准

### 10.1 准备页验收

必须满足：

1. 页面内不再出现“器械导入功能将通过 CTK 服务实现”这类占位提示
2. 页面只展示病例工作包中已绑定器械与几何文件
3. 标定动作可用，标定状态、采样进度、完成状态能真实刷新
4. 若工作包缺 geometry 或器械，页面明确显示阻塞原因

### 10.2 规划页验收

必须满足：

1. 页面不再出现旧分割 / 旧导模主流程按钮
2. 页面能展示 `target_bone`、`target_region`、`constraint_regions`、`recommended_registration_point_order`
3. 页面保留病例已绑定骨模型 / 影像的只读查看能力
4. 页面展示内容与 `planning_state` 一致

### 10.3 配准页验收

必须满足：

1. 页面不再保留 2D-3D 占位入口
2. 页面支持采点、删点、清点、计算配准
3. 页面能展示分骨 / 分部位结果与融合导航空间状态
4. 页面展示内容与 `registration_state` 一致

### 10.4 导航页验收

必须满足：

1. 页面从旧四视图切换为单一 3D 虚拟空间
2. 该空间能显示骨 STL + 当前器械 STL + 实时位姿
3. tracking 丢失时器械进入隐藏或不可用状态
4. 页面显示内容与 `NavigationDisplayState` 一致

### 10.5 评估页验收

必须满足：

1. 页面能展示配准误差、分骨质量、tracking latency / jitter / visible frame ratio、导航过程摘要
2. 页面支持病例级评估报告导出
3. 页面展示内容与 `evaluation_state` 一致

### 10.6 整体验收

必须满足：

1. 五阶段都只消费病例工作包真源
2. 页面中不再混有误导性的旧占位交互
3. 用户能在软件中直接看到这轮开发后的实际效果，而不是只能看到后台能力存在

## 11. 实施顺序建议

### 第一阶段：旧入口清退

- 先移除准备 / 规划 / 配准中的旧导入、旧分割、旧 2D-3D 占位入口
- 先消除假功能，避免继续误导

### 第二阶段：五阶段页面真实收口

- 分别收口准备页、规划页、配准页、评估页
- 让页面展示内容和当前快照模型一一对应

### 第三阶段：导航页单窗口收口

- 切换导航阶段主界面为单一 3D 虚拟空间
- 对接现有 digital twin backend

### 第四阶段：最小可用联调

- 走一次病例主链
- 验证：
  - 五阶段页面
  - 阶段门禁
  - 分骨结果
  - 单窗口导航
  - 评估摘要

## 12. 成功判定

这份设计成功落地的标志是：

- 导航工作区页面终于和现有 specs / plans 的真实能力重新一致
- 用户在软件里看到的功能，不再是旧壳层、占位按钮和误导性入口
- 工作区聚合、数字孪生链路和五阶段页面形成同一条可见、可操作、可联调的主路径
