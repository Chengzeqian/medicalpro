# UI Phase 2 Three Pages Design

**日期：** 2026-04-14  
**范围：** `WelcomePage`、`ModuleSelectionPage`、`DashboardPage`  
**目标：** 在不推翻现有 `Qt Widgets + .ui + NewPages` 架构的前提下，把三页从“能用”提升为“正式产品化入口/门厅/工作台”。

## 1. 设计目标
- 延续 Phase 1 已建立的主题令牌与公共 QSS。
- 不破坏现有页面跳转与 CTK 服务调用主链路。
- 强化三页的信息层级、专业感和一致性。
- 让 Welcome / ModuleSelection / Dashboard 像同一套医疗工作站产品，而不是三个孤立页面。

## 2. 整体视觉原则
- 基调：深蓝医疗工作站背景，辅以冷色高光和克制的强调色。
- 风格：正式、专业、可信、可调试。
- 结构优先级：先建立稳定的信息层级，再补视觉装饰。
- 动效原则：只保留必要的进入、hover、CTA 反馈，不做花哨动画。
- 工程原则：优先复用现有主题令牌、公共 QSS 与页面结构，不引入高风险框架切换。

## 3. WelcomePage 设计

### 3.1 定位
WelcomePage 不再只是“启动页”，而是系统正式产品入口。

### 3.2 版式
采用：`Hero 主导 + 状态卡横排 + 底部双按钮`

信息顺序：
1. 系统标识 / 产品名
2. 主标题：`智能手术导航工作站`
3. 副标题：强调精准、稳定、可进入正式工作流
4. 三张真实状态卡
5. `进入系统` 主按钮
6. `退出系统` 次按钮

### 3.3 三张真实状态卡
- `插件框架`
  - 状态：已初始化 / 未初始化 / 初始化失败
  - 可带简短框架阶段说明
- `关键服务`
  - 采用服务组汇总，不展示展开列表
  - 首批建议汇总：`UserManagement`、`DicomViewer`、`FourViewDisplay`
  - 文案：已就绪 / 部分异常 / 未就绪
- `数据目录`
  - 检查关键目录是否存在、可访问
  - 文案：在线 / 缺失 / 不可访问

### 3.4 状态刷新策略
- 进入 WelcomePage 时检测一次
- 不做持续定时刷新
- 目标是在产品感和调试信息之间取得平衡

### 3.5 交互原则
- `进入系统` 是唯一强 CTA
- 状态卡默认只展示摘要，不承载复杂操作
- 状态异常时做视觉提示，但不把欢迎页变成错误面板

## 4. ModuleSelectionPage 设计

### 4.1 定位
ModuleSelectionPage 从“两个按钮页”升级为“正式模块门厅页”。

### 4.2 版式
采用：`中央双主卡 + 顶部状态条`

### 4.3 顶部状态条
显示：
- 访客身份
- 当前时间
- 系统状态
- 返回欢迎页

### 4.4 双主卡结构
每张卡包含：
- 模块名
- 一句说明
- 状态标签
- 进入按钮

### 4.5 主次关系
- `踝关节手术导航` 为主业务卡，视觉上更强
- `系统设置` 为次级卡，弱化但保留

### 4.6 设计目标
- 让用户一眼看清当前最重要的业务入口
- 同时保留系统设置这一系统级入口
- 为未来模块增加保留可扩展空间

## 5. DashboardPage 设计

### 5.1 定位
DashboardPage 从“详情堆叠页”升级为“病例工作台”。

### 5.2 版式
采用：`左侧患者列表 + 右侧工作区`

### 5.3 右侧工作区结构
- 顶部：概览卡
- 中部：病例详情区 / DICOM 相关信息区
- 底部：`进入导航` 强 CTA

### 5.4 顶部概览卡内容
- 患者基本信息
- 诊断
- 主治医生
- DICOM 数量

### 5.5 设计目标
- 让用户先快速建立病例全局认知
- 再查看详情
- 最后执行“进入导航”主动作

## 6. 数据与状态来源原则
- WelcomePage 的三张状态卡优先使用真实运行状态。
- ModuleSelectionPage 顶部状态条使用真实时间与真实系统状态。
- Dashboard 保持现有真实病例与 DICOM 数据流，不新增与现有业务冲突的数据模型。

## 7. 不在本阶段处理的内容
- 不切换到 QML。
- 不在这一轮引入新的高风险 UI 框架替换主页面架构。
- 不在欢迎页展开详细服务日志列表。
- 不在 Dashboard 一次性做成多停靠复杂工作区。

## 8. 实施顺序
1. WelcomePage 视觉升级与真实状态卡接入
2. ModuleSelectionPage 门厅化改版
3. Dashboard 工作台化改版
4. 三页稳定后，再评估更高层 UI 能力扩展

## 9. 验收标准
- 三页视觉语言统一，明显属于同一套产品。
- WelcomePage 保留且无需登录。
- WelcomePage 能看到真实运行状态摘要。
- ModuleSelectionPage 不再像临时过渡页，而是正式门厅页。
- Dashboard 的信息层级清楚，`进入导航` 成为明确主动作。
- 不破坏现有 CTK 服务加载、页面跳转和插件运行主链路。
