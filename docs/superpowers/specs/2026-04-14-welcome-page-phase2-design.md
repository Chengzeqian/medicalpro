# WelcomePage Phase 2 Design

**日期：** 2026-04-14  
**范围：** `UI/NewPages/WelcomePage.*`、`UI/Forms/WelcomePage.ui`、相关公共主题层  
**目标：** 在不改变 `Qt Widgets + .ui + NewPages` 架构、不跳过欢迎页、不恢复登录流程的前提下，把 WelcomePage 从“可进入页面”升级为“医疗旗舰工作站入口页”。

## 1. 设计目标

- 保留 WelcomePage 作为系统启动后的第一页。
- 用户不需要登录，但仍然必须从 WelcomePage 进入系统。
- WelcomePage 需要在视觉上体现“医疗旗舰工作站”的专业感，而不是普通启动页或宣传页。
- WelcomePage 需要承接真实运行状态摘要，让用户在进入系统前快速判断当前是否适合继续主流程。
- 设计必须可以稳定落地到现有 `Qt Widgets + QSS` 体系，不依赖 QML 或高风险 UI 框架切换。

## 2. 页面定位

WelcomePage 是 MedicalPro 的正式产品入口页，不再只是过渡页面。它承担三件事：

1. 建立系统品牌感和入口仪式感。
2. 给出当前运行状态的简明结论。
3. 通过单一主动作把用户导向 `ModuleSelectionPage`。

页面不承担登录、复杂诊断、详细日志展示或模块导航分流职责。

## 3. 视觉方向

### 3.1 总体气质

- 关键词：`医疗旗舰`、`专业克制`、`工作站启动台`
- 不采用宣传海报风。
- 不采用互联网登录页风格。
- 不依赖夸张动画或大面积装饰图。

### 3.2 背景与材质

- 页面主背景采用深蓝灰渐变，建议从 `#0B1722` 过渡到 `#102738`。
- 背景可加入低对比几何网格或柔和扫描光晕，增强“设备工作站”氛围。
- 主视觉区和状态区使用深色实体面板感。
- 面板采用低对比边框和轻阴影，不做厚重悬浮。

### 3.3 色彩体系

- 主强调色：医疗青蓝 `#38C6D9`
- 辅助高亮：设备琥珀 `#F3A53B`
- 成功色：`#34C38F`
- 警告色：`#F0B54A`
- 异常色：`#E06C75`

### 3.4 动效原则

- 页面进入仅使用轻微淡入和上移。
- 按钮与卡片 hover 仅做轻微提亮和阴影变化。
- 不做复杂连续动画，不影响启动效率和专业感表达。

## 4. 版式结构

页面采用“上方主视觉区 + 下方状态卡区”的双层结构。

### 4.1 上方主视觉区

上方主视觉区为左右双区布局。

- 左侧品牌欢迎区约占 `58%`
- 右侧运行摘要区约占 `42%`

### 4.2 左侧品牌欢迎区

左侧区域包含：

- Logo 或品牌标识
- 眉标题
- 主标题
- 副标题
- `进入系统` 主按钮
- `退出` 次按钮

左侧区域承担页面主要视觉重心，主标题与主按钮应成为首屏最强焦点。

### 4.3 右侧运行摘要区

右侧区域包含：

- `当前运行状态` 标题
- 一行系统摘要
- 3 条核心速览
- 底部状态结论标签

右侧区域用于表达“当前系统是否可进入”，但不替代日志窗口或故障详情页。

### 4.4 下方状态卡区

下方固定为 3 张状态卡：

- `插件框架`
- `关键服务`
- `数据目录`

这三张卡用于把右侧摘要中的核心判断拆成更易读的状态面板，但仍然保持轻量，不展开复杂细节。

## 5. 文案体系

### 5.1 左侧主文案

- 眉标题：`MEDICALPRO SURGICAL WORKSTATION`
- 主标题：`智能手术导航工作站`
- 副标题：`面向术前准备、病例管理与导航流程的统一入口`

### 5.2 右侧摘要文案

- 区块标题：`当前运行状态`
- 一行摘要：`插件框架已联通，关键服务持续自检中，系统当前处于可进入状态。`

### 5.3 三条核心速览文案

- `插件框架：已识别 X 个插件`
- `关键服务：X/3 已就绪`
- `数据目录：data 可访问`

### 5.4 状态结论文案

- 正常：`主流程可进入`
- 非阻塞异常：`可进入，建议检查`
- 阻塞：`暂不建议进入`

### 5.5 按钮文案

- 主按钮：`进入系统`
- 次按钮：`退出`

## 6. 信息结构

### 6.1 右侧运行摘要区结构

右侧摘要区采用自上而下的单列结构：

1. 区块标题
2. 一行总摘要
3. 3 条核心速览
4. 1 个最终状态结论标签

每条速览固定为：`名称 + 当前值 + 状态徽标`

### 6.2 下方三张状态卡结构

每张状态卡包含：

- 卡片标题
- 主状态文字
- 简短摘要
- 一条辅助说明

三张卡的信息定义如下：

#### 插件框架卡

- 作用：显示插件系统是否已完成初始化
- 主信息：插件数量、策略已加载与否、当前状态
- 辅助说明示例：`RegistrationCore 已纳入延迟加载策略`

#### 关键服务卡

- 作用：显示核心服务整体健康度
- 主信息：已就绪服务数
- 辅助说明示例：`DICOM / 导航 / 数据服务状态摘要`

#### 数据目录卡

- 作用：显示运行目录、配置和数据访问是否正常
- 主信息：目录可访问性
- 辅助说明示例：`Debug / Release 配置已同步`

### 6.3 信息密度控制

- WelcomePage 只做“进入前确认”，不承担详细排障职责。
- 页面不直接展示长日志。
- 页面不展示模块级详细告警列表。
- 页面主动作始终只有 `进入系统`。

## 7. 状态与交互规则

### 7.1 页面主动作

- `进入系统` 是页面唯一主 CTA。
- 点击后进入 `ModuleSelectionPage`。
- 不恢复登录流程，不跳过 WelcomePage。

### 7.2 次动作

- `退出` 保留为次级动作。
- 视觉上降级为描边或低对比按钮。

### 7.3 状态展示规则

- 右侧摘要区默认不承担跳转入口。
- 下方 3 张状态卡第一阶段以状态展示为主，不加入复杂点击行为。
- hover 仅用于轻微反馈，不暗示它们是主导航入口。

### 7.4 状态颜色规则

- 绿色：可进入、已就绪、可访问
- 琥珀：可进入但建议检查
- 红色：阻塞、未就绪、不可访问
- 青蓝：中性信息、数量、辅助说明

## 8. 尺寸与响应式规则

### 8.1 页面边距

- 桌面宽屏：外边距 `32px`
- 常规窗口：外边距 `24px`
- 较窄窗口：外边距 `16px`
- 主视觉区与状态卡区之间留白 `24px`

### 8.2 主视觉区尺寸

- 最小高度建议：`360px`
- 推荐高度区间：`380px ~ 440px`
- 左右两区间距：`24px`

### 8.3 左侧品牌欢迎区尺寸

- Logo / 品牌区高度：`40px ~ 56px`
- 眉标题字号：`12px ~ 13px`
- 主标题字号：`36px`
- 副标题字号：`16px`
- 主标题与副标题间距：`16px`
- 副标题与按钮区间距：`24px`
- 主次按钮间距：`12px`

### 8.4 右侧运行摘要区尺寸

- 面板内边距：`24px`
- 区块标题字号：`20px`
- 一行摘要字号：`14px ~ 15px`
- 三条速览垂直间距：`14px`
- 结论标签与速览区间距：`18px`
- 结论标签高度：`32px ~ 36px`

### 8.5 状态卡尺寸

- 每张卡最小宽度：`220px`
- 推荐高度：`132px ~ 148px`
- 卡片内边距：`20px`
- 卡片标题字号：`16px`
- 主信息字号：`20px`
- 副信息字号：`13px ~ 14px`
- 卡片横向间距：`16px`

### 8.6 按钮尺寸

- `进入系统`：高度 `48px`，最小宽度 `160px`，圆角 `12px`
- `退出`：高度 `44px`，最小宽度 `112px`，圆角 `12px`

### 8.7 响应式规则

- 宽屏：上方左右双区，下方三卡横向一排
- 中等宽度：上方保持左右布局，下方三卡改为 `2 + 1`
- 较窄宽度：上方改为上下布局，下方三卡纵向堆叠
- 再窄时：主标题允许换行，右侧摘要保持单列，不压缩成双列

## 9. 实现边界

- 设计必须可直接落地到 `Qt Widgets + QSS`。
- 布局以 `QVBoxLayout`、`QHBoxLayout`、`QGridLayout` 为主，不依赖绝对定位硬压结构。
- 不依赖模糊玻璃、复杂 shader、视频背景、大图像背景等高风险效果。
- 本阶段不引入 QML。
- 本阶段不要求改造为可停靠工作区结构。
- 后续若评估 `QWindowKit` 或 `KDDockWidgets`，WelcomePage 的结构与视觉语言应可直接延续。

## 10. 非目标

- 不跳过 WelcomePage。
- 不恢复登录页面作为必经入口。
- 不在 WelcomePage 展示详细控制台日志。
- 不在本阶段引入新的 UI 框架替换现有主页面架构。

## 11. 验收标准

- 程序启动后第一页仍然是 WelcomePage。
- WelcomePage 同时具备品牌入口感、运行摘要和进入系统主动作。
- 页面视觉语言明显强于当前版本，并符合“医疗旗舰工作站”方向。
- `进入系统` 仍然进入 `ModuleSelectionPage`。
- 页面不要求登录。
- 状态区能够承接真实运行状态摘要，不只是静态装饰。
- 页面结构和样式可以稳定落地到当前 `Qt Widgets + QSS` 工程。
