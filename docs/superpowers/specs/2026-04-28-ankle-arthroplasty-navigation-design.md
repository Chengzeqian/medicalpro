# Ankle Arthroplasty Navigation Design

**日期：** 2026-04-28  
**范围：** `medicalpro` 毕业项目主线，聚焦 `踝关节置换导航` 的完整链路设计  
**目标：** 在不引入重型外部运行时框架的前提下，以 `medicalpro` 为主体，构建一条从术前影像到术中导航评估的完整闭环，并围绕配准与导航可信度形成 3 个可对比、可验证、可写论文的创新点。

## 1. 项目定位

本项目定位为：

> 面向踝关节置换的术前影像驱动光学导航系统设计与关键方法优化

本项目是硕士毕业项目，不追求商业级全产品覆盖，而追求以下三点同时成立：

- 有一条完整、可演示、可重复的系统链路
- 有至少 3 个明确创新点，且至少 1 个为算法创新
- 创新点建立在已有经典方法和临床需求之上，能够做客观对比

## 2. 已确认边界

### 2.1 运行时边界

- `medicalpro` 是唯一运行时主系统
- `3D Slicer` 仅承认是历史分割数据制备来源，不进入运行时依赖
- `OpenIGTLink` 和 `Plus Toolkit` 只作为可选桥接能力，不作为首版闭环前提
- 首版主验收以 `仿真 / 回放闭环` 为主，`真实光学跟踪接入` 为加分项

### 2.2 数据边界

- 当前数据条件为少量自有数据，适合做小规模可重复验证，不适合做大样本深度学习论文
- 同门已有通过 `3D Slicer` 分割好的骨模型或标签结果，可以作为术前预分割输入
- 论文主线不将“自动分割模型创新”作为核心贡献

### 2.3 临床场景边界

- 主场景固定为 `踝关节置换导航`
- 首版对象聚焦 `胫骨 + 距骨`
- `腓骨` 作为可选增强对象，不进入首版硬性范围

## 3. 设计目标

### 3.1 系统目标

系统需要打通如下闭环：

`CT/DICOM导入 -> 预分割结果/骨模型导入 -> 术前规划与标注 -> 术中采点与多阶段配准 -> 光学导航显示 -> 误差评估与实验记录`

### 3.2 论文目标

论文需要形成以下可答辩结构：

- 一套可运行的踝关节置换导航原型系统
- 一套面向目标区精度优化的配准方法
- 一套面向导航准入的可信度评估机制
- 一组与经典基线可对比的实验结果

## 4. 非目标

以下内容不在首版范围内：

- 不重做完整分割平台，也不以分割网络训练作为论文主创新
- 不迁移到 `3D Slicer` 或 `MITK` 作为新宿主框架
- 不做大样本临床统计研究
- 不做多术式泛化平台，首版只服务踝关节置换
- 不把真实硬件接入作为链路完成的前提

## 5. 现有工程复用策略

本设计默认复用当前项目中已经具备的主能力，而不是推倒重来。

### 5.1 直接复用模块

- `DicomViewer`：术前 CT / DICOM 导入与显示
- `FourViewDisplay`：四视图与体数据显示
- `BoneSegmentation`：保留作为可选自动分割能力和对照入口
- `PointRegistration`：点配准流程骨架
- `RegistrationCore`：底层配准算法承载
- `OpticalTracking`：跟踪、回放、采点、校准接口
- `InstrumentManagement`：器械模型与导航工具管理
- `NavigationPage`：统一工作区宿主

### 5.2 新增模块

首版只新增 2 个聚焦模块：

- `AnklePlanning`
  - 负责预分割模型导入后的术前规划
  - 负责解剖点、目标区、假体目标位姿等规划信息定义
- `NavigationEvaluation`
  - 负责配准质量、导航偏差、实验指标和结果导出
  - 直接服务论文图表、表格和实验留痕

## 6. 总体架构

系统采用“现有宿主 + 轻量新增业务模块”的结构：

### 6.1 表现层

- 入口页：`WelcomePage`、`ModuleSelectionPage`
- 病例上下文页：`ManagementPage`、`DashboardPage`
- 核心工作区：`NavigationPage`

### 6.2 业务编排层

- 病例上下文管理
- 术前规划管理
- 配准流程编排
- 导航状态管理
- 评估与实验记录管理

### 6.3 算法与服务层

- 影像显示服务
- 分割导入与模型服务
- 点配准与表面配准服务
- 跟踪与回放服务
- 误差评估与可信度评分服务

### 6.4 数据资产层

- 病例目录
- 规划文件
- 配准结果文件
- 导航日志
- 评估报告与导出表格

## 7. 页面与工作流设计

不新增顶层页面体系，沿用现有页面流：

`Welcome -> ModuleSelection -> Management -> Dashboard -> Navigation`

### 7.1 ManagementPage 职责

- 建立病例、患者、手术任务上下文
- 输出明确的 `case_id + surgery_id`

### 7.2 DashboardPage 职责

- 显示当前病例状态
- 检查术前影像、分割、规划、配准准备状态
- 作为进入导航工作区前的收口页

### 7.3 NavigationPage 职责

`NavigationPage` 作为唯一核心工作区，但内部重组为五段式流程：

1. `准备`
2. `规划`
3. `配准`
4. `导航`
5. `评估`

其职责不再是“堆功能按钮”，而是承载完整论文主链路。

## 8. 数据流与资产组织

### 8.1 病例目录结构

每个手术任务使用一个统一工作目录：

```text
data/cases/<case_id>/
  dicom/
  segmentation/
  models/
  planning/
  registration/
  navigation/
  evaluation/
```

### 8.2 关键数据文件

#### `case_manifest.json`

记录：

- 病例基本信息
- DICOM 路径
- 预分割标签或模型路径
- 当前流程状态

#### `planning.json`

记录：

- 胫骨 / 距骨模型引用
- 解剖标志点
- 配准参考点
- 目标区定义
- 假体目标位姿
- 截骨相关参考平面或轴线

#### `registration_result.json`

记录：

- `T_image_to_patient`
- 点配准结果
- 表面精配准结果
- `FRE`
- `TRE`
- 目标区 `TRE`
- 质量等级

#### `navigation_run.json`

记录：

- 导航开始时间
- 轨迹数据索引
- 采样频率
- 可信度状态变化
- 偏差告警记录

#### `evaluation_report.json`

记录：

- 配准精度指标
- 导航偏差指标
- 角度与位姿误差
- 运行效率指标
- 实验结论摘要

#### `evaluation_metrics.csv`

用于导出论文表格和后续统计分析。

## 9. 五段式主链路定义

### 9.1 准备阶段

输入：

- `DICOM` 目录
- 已分割 `NIfTI / STL / PLY`
- 病例基本信息

输出：

- 标准化病例目录
- `case_manifest.json`
- 统一后的模型与影像引用

目标：

- 统一命名、路径和坐标资产
- 为后续规划和配准提供稳定输入

### 9.2 规划阶段

输入：

- CT 体数据
- 胫骨 / 距骨模型

输出：

- `planning.json`

内容包括：

- 解剖标志点
- 目标区
- 目标位姿
- 配准参考点
- 评估参考结构

该阶段由 `AnklePlanning` 承担。

### 9.3 配准阶段

输入：

- `planning.json`
- 术中采点或回放点
- 可选表面点云

输出：

- `registration_result.json`

固定采用两阶段流程：

1. 基于解剖点的粗配准
2. 基于局部表面区域的精配准

### 9.4 导航阶段

输入：

- `registration_result.json`
- 跟踪器实时位姿或回放数据
- 器械模型与探针标定结果

输出：

- `navigation_run.json`
- 轨迹记录
- 关键帧截图
- 偏差告警

默认以仿真 / 回放完成闭环，真实硬件只替换位姿输入源。

### 9.5 评估阶段

输入：

- 规划目标
- 配准结果
- 导航日志

输出：

- `evaluation_report.json`
- `evaluation_metrics.csv`

该阶段由 `NavigationEvaluation` 承担。

## 10. 三个创新点设计

### 10.1 创新点一：面向假体目标区的配准点智能选取

#### 核心问题

传统点配准中，采点位置往往依赖经验或随机分布，难以保证目标区 `TRE` 最优。

#### 设计思路

结合踝关节置换规划信息，对候选解剖点或候选表面采点区域进行评分，优先推荐对目标区 `TRE` 更敏感的点位组合。

#### 实现方向

- 以假体目标区、目标轴线、目标面为中心定义“目标敏感区域”
- 结合点到目标区的几何关系、点集空间分布和角度覆盖度计算点位优先级
- 术中采点时给出推荐顺序或覆盖度反馈

#### 对照基线

- 人工经验选点
- 均匀 / 随机选点

#### 主要指标

- 目标区 `TRE`
- 同等点数下误差下降幅度
- 达到可接受误差所需采点数

### 10.2 创新点二：踝关节解剖约束的双阶段配准算法

#### 核心问题

全局点配准或全局 ICP 在踝关节局部复杂骨面、遮挡和采点不均条件下，容易出现局部最优或目标区误差偏大。

#### 设计思路

采用：

1. `加权刚性点配准`
2. `ROI 约束的局部表面精配准`

第一阶段通过解剖点完成稳定初始化，第二阶段仅在高信息量的局部骨面区域做 refinement，对低稳定区域降权。

#### 实现方向

- 粗配准使用 landmark 加权刚性配准
- 精配准在胫骨远端关节面、距骨穹隆等 ROI 范围内执行
- 引入局部曲率、法向一致性和区域可信度权重

#### 对照基线

- 普通刚性点配准
- 点配准 + 全局 ICP
- 点配准 + 全局 GICP

#### 主要指标

- `FRE`
- `TRE`
- 平移误差
- 姿态角误差
- 收敛时间
- 配准成功率

### 10.3 创新点三：配准-跟踪联合可信度评估与导航准入机制

#### 核心问题

仅凭 `FRE` 或单一残差阈值决定“是否允许进入导航”不够可靠，不能有效识别点分布差、跟踪抖动大、目标区误差高的坏配准。

#### 设计思路

构建统一的 `navigation confidence score`，将以下因素联合起来：

- 预测 `TRE`
- 表面配准残差
- 采点覆盖度
- 跟踪器抖动程度
- 遮挡或丢帧状态

并基于该评分做导航准入、重试建议和风险提示。

#### 对照基线

- 仅用 `FRE` 单阈值放行
- 仅用 `RMS` 单阈值放行

#### 主要指标

- 低质量配准识别率
- 错误放行率
- 重试次数
- 导航阶段中位目标偏差

## 11. 实验验证方案

### 11.1 总体策略

采用三层验证体系：

1. 算法离线验证
2. 回放 / 仿真闭环验证
3. 真实硬件可选验证

### 11.2 数据建议

- 目标病例数：5 到 10 例可完整运行的踝关节 CT / 预分割数据
- 主体结构：胫骨、距骨
- 必要时扩展结构：腓骨

### 11.3 扰动设计

为验证算法与系统稳健性，需要在回放或离线实验中加入：

- 采点噪声
- 漏点
- 点分布不均
- 跟踪抖动
- 短时遮挡

### 11.4 主指标

#### 配准精度

- `FRE`
- `TRE`
- 目标区 `TRE`

#### 位姿偏差

- 平移误差 `mm`
- 角度误差 `deg`

#### 规划相关偏差

- 目标点偏差
- 目标轴线偏差
- 目标面法向偏差

#### 稳健性

- 配准成功率
- 低质量配准识别率
- 错误放行率

#### 效率

- 达到可接受误差所需采点数
- 单次配准耗时
- 完整链路总耗时

## 12. 验收标准

系统完成需满足以下硬验收条件：

1. 能从病例选择进入踝关节置换工作流，并完成 CT / 模型 / 规划数据加载
2. 能导入既有分割结果，并生成统一规划上下文
3. 能完成至少一种稳定的两阶段配准，并输出变换矩阵与质量评估
4. 能在回放 / 仿真模式下稳定运行导航，并输出工具位姿叠加和偏差提示
5. 能自动生成评估结果文件，至少包含 `FRE / TRE / 目标偏差 / 耗时 / 日志索引`

## 13. 风险与控制

### 13.1 风险：分割质量不一致

控制：

- 首版不依赖系统内自动分割
- 优先消费已有高质量预分割结果
- 将模型检查和必要修正前置到规划阶段

### 13.2 风险：真实硬件环境不稳定

控制：

- 首版主验收走回放 / 仿真
- 将真实硬件接入设计为可替换输入源

### 13.3 风险：样本量较小

控制：

- 不做大样本训练型创新
- 强化基线对照和重复实验
- 提高每例病例的完整链路可复现性

### 13.4 风险：工作区功能继续无序堆叠

控制：

- 严格按五段式流程重构 `NavigationPage`
- 新增能力必须挂靠到 `准备 / 规划 / 配准 / 导航 / 评估` 之一

## 14. 开发阶段划分

后续实施严格分为 4 个阶段：

### 阶段 A：病例与规划闭环

目标：

- 打通 CT / 预分割 / 模型导入
- 生成 `case_manifest.json`
- 生成 `planning.json`

### 阶段 B：配准闭环

目标：

- 实现目标敏感选点
- 实现双阶段配准
- 生成 `registration_result.json`

### 阶段 C：导航与准入闭环

目标：

- 实现回放 / 仿真导航
- 实现可信度准入
- 生成 `navigation_run.json`

### 阶段 D：实验与论文闭环

目标：

- 固化实验脚本
- 输出评估报表
- 生成论文图表和结果素材

## 15. 参考依据

本设计的关键判断建立在以下公开资料与经典方法之上：

- `3D Slicer` 可作为历史分割数据来源，但不作为本项目运行时依赖
- `OpenIGTLink` 适合作为图像引导手术实时设备通信协议
- `Plus Toolkit` 适合作为可选跟踪桥接和回放输入源
- `FRE` 与 `TRE` 的区别说明目标区误差需要单独建模和评估
- `ICP / GICP` 等经典刚性配准方法可作为稳定对照基线

## 16. 最终结论

本项目不再以“继续治理 CTK 或继续堆功能”为目标，而是正式转入毕业项目主线：

> 以 `medicalpro` 为主体，围绕踝关节置换场景，构建一条从术前影像到术中导航评估的完整链路，并在目标敏感选点、解剖约束配准、导航准入可信度三个方面完成可量化创新。

后续实施计划必须围绕该设计展开，不再新增与该主线无关的功能分叉。
