# UI Phase 2 Visual Polish Design

**日期：** 2026-04-15  
**范围：** `WelcomePage`、`ModuleSelectionPage`、`ManagementPage`、`DashboardPage` 的人工视觉验收向微调  
**目标：** 在不改页面主结构、不改业务流程、不新增复杂交互的前提下，对四页进行克制型视觉收口，让页面层级、留白、按钮强弱、卡片对比度与标题节奏更稳定、更像同一套正式医疗工作站产品。

## 1. 设计定位

这轮不是重新设计，而是基于当前已经落地的 Phase 2 页面做“验收向微调”：

- 不改主链：`Welcome -> ModuleSelection -> Management -> Dashboard`
- 不推翻当前页面骨架
- 不增加新的信息模块
- 不引入更花哨的视觉语言
- 只做视觉秩序、主次关系和信息密度优化

一句话定义：

> 让四页从“已经能看”提升到“更稳、更清楚、更像正式产品”。

## 2. 总体微调原则

### 2.1 保持克制

- 避免更强的发光、炫技式渐变、夸张阴影
- 继续保持医疗工作站的冷静、可靠、专业感
- 通过层级和留白，而不是更多视觉特效，来建立重点

### 2.2 强化主次

- 每页必须有明确第一视觉焦点
- 主要 CTA 必须明显强于次级操作
- 状态信息可以保留，但不能抢主流程入口的注意力

### 2.3 降低平均化

当前四页共同的问题不是信息不够，而是很多模块“都差不多重要”。

本轮要解决的是：

- 标题区更像标题区
- 内容区更像内容区
- 辅助状态更像辅助状态
- 让用户一眼知道“先看哪，再点哪”

## 3. 分页微调策略

### 3.1 WelcomePage

当前方向是对的，下一步重点是继续拉开左主右辅关系。

本页微调目标：

- 左侧品牌主视觉继续作为第一页焦点
- 右侧运行摘要继续保留，但视觉竞争感再降半级
- 主按钮 `进入系统` 再更明确
- 次按钮 `退出` 继续弱化
- 下方三张状态卡保持存在，但进一步减少“压屏”的感觉

具体策略：

- 收紧右侧摘要区和底部状态卡的对比度
- 适度压缩次级文本密度
- 加强主按钮尺寸、边框和亮度优势
- 继续让品牌区成为第一落点

### 3.2 ModuleSelectionPage

当前页面已经具备门厅感，但主模块卡和辅助模块卡之间仍可进一步拉开。

本页微调目标：

- `ankleSurgeryCard` 明确成为唯一主卡
- `systemSettingsCard` 再后退半级
- 头部状态条存在感保留，但不抢 Hero 区
- 按钮、标题、状态标签形成清晰的阅读顺序

具体策略：

- 提升主卡背景对比和按钮权重
- 降低系统设置卡的边框存在感和视觉兴奋度
- 微调 Hero 区与卡区间距
- 让主卡 CTA 比当前更像“继续主流程”

### 3.3 ManagementPage

当前中台壳层已经搭起来，下一步重点是消除“信息都很重”的感觉。

本页微调目标：

- 顶部 header 更利落
- 三张概览卡更像摘要，不像第二套主内容区
- 当前工作视图上下文条更紧凑
- 表格区更清爽，减少界面拥挤感
- 底部 CTA 更稳，像流程收口，而不是额外卡片

具体策略：

- 压缩上下文条和内容容器的留白
- 降低概览卡文字密度
- 让概览卡状态标签从“强调信息”改为“辅助提示”
- 调整底部 CTA 的按钮与说明比例，让按钮更果断、说明更收敛

### 3.4 DashboardPage

当前工作台已经成型，下一步重点是减少顶部和中部信息的平均铺开感。

本页微调目标：

- 进一步突出当前病例和导航动作
- 顶部信息带更紧凑
- 中部三块内容区层级更清楚
- 底部 CTA 比现在更像“流程下一步”

具体策略：

- 强化病例名和主导航按钮
- 收紧概览卡高度与留白
- 弱化不重要的辅助标题
- 让 CTA 视觉重心从“状态说明”转向“可执行动作”

## 4. 样式层处理原则

- 优先改 `UI/styles/three_pages_theme.qss`
- 仅在必要时对页面类做少量文案或控件属性微调
- 不回到 `.ui` 中堆大量内联样式
- 不做大面积对象名重构

本轮更适合的改法是：

- 调整现有对象样式权重
- 优化边框、背景、字号、按钮高度、卡片间距
- 在现有对象名基础上直接收口

## 5. 不在本轮处理的内容

- 不新增页面
- 不改跳转链
- 不改欢迎页品牌方案
- 不改插件链问题
- 不改控制台日志链
- 不做新的交互组件
- 不做“更炫”的大幅视觉风格切换

## 6. 验收标准

- Welcome 页进入时，第一眼明显落在左侧品牌区和主按钮
- ModuleSelection 页里，用户能直觉感受到“主流程入口”比系统设置更重要
- Management 页不再显得拥挤或平均用力，概览卡、表格区、底部 CTA 的主次更清晰
- Dashboard 页里，当前病例与导航下一步的优先级明显高于辅助信息
- 四页整体保持统一视觉语言，但每页仍保留自己在流程中的角色差异

## 7. 实施顺序

1. 优先调整公共 QSS 中四页的层级、留白、按钮与卡片权重
2. 少量修改 `WelcomePage.cpp`、`ModuleSelectionPage.cpp`、`ManagementPage.cpp`、`DashboardPage.cpp` 的文案或控件属性
3. 构建验证
4. 启动程序做一轮新的人工视觉验收

## 8. 2026-04-16 第二轮验收向微调策略

本轮继续沿用既有视觉方向，不换风格、不改主链、不碰插件链，核心主题收口为：

> 纵向压缩 + 信息聚焦

本轮具体策略如下：

- WelcomePage
  - 压缩左侧品牌区到按钮之间的垂直空白
  - 收窄右侧运行摘要区宽度，降低摘要卡高度感
  - 继续压薄底部三张状态卡，让主按钮保持第一视觉落点
- ModuleSelectionPage
  - 压缩顶部状态条与 Hero 的上下边距
  - 明显降低 `ankleSurgeryCard` / `systemSettingsCard` 的卡片高度
  - 去掉按钮前的过度弹性留白，让 CTA 自然上提
- ManagementPage
  - 压缩 Header、概览卡、当前工作视图上下文条和底部流程 CTA
  - 进一步降低 Tab、搜索栏、表头与行高的厚度
  - 让表格区成为真正主内容，减少“内容没装满”的观感
- DashboardPage
  - 压缩顶部 Header、概览条、详情区内边距与底部 CTA
  - 弱化大面积浅底块感，统一回深色工作台节奏
  - 压缩 DICOM 区和 DICOM 卡片尺寸，让病例与导航动作更聚焦

本轮验收标准补充为：

- 四页在 1080p 常见桌面窗口下应明显减少纵向空白堆积
- 用户视线应更快落到每页主 CTA，而不是停在高卡片或大空白上
- 页面仍保持同一套医疗工作站视觉语言，但层级更紧、更聚焦

## 9. 2026-04-16 第三轮微调策略

本轮基于真实运行截图继续做人工视觉验收向微调，核心目标从“纵向压缩 + 信息聚焦”进一步收口为：

> Welcome 主视觉放大，四页主流程层级更明确。

### 9.1 WelcomePage
- 放大 logo、主标题、主按钮区域，让第一页���像正式首页而不是过渡页。
- 把额外高度优先分配给主视觉区，而不是留给底部空白。
- 继续弱化右侧运行摘要卡的存在感，让其承担辅助信息，不与左侧主入口竞争。

### 9.2 ModuleSelectionPage
- 限制顶部状态条和 Hero 区的纵向膨胀，避免页面重心过高。
- 让数据管理主卡承担更多视觉权重，系统设置卡继续保持辅助入口定位。

### 9.3 ManagementPage
- 维持当前结构不变，仅做低风险密度收口。
- 表头、行高、上下文条和底部 CTA 继续压缩，减少空场和浅色跳点。

### 9.4 DashboardPage
- 收紧 header、概览条和底部 CTA 高度，减少顶部堆叠感。
- 统一详情区和 DICOM 区的深色工作台语义，削弱突兀灰底。
- DICOM 空态和缩略卡继续收口，避免抢主病例信息。

### 9.5 本轮边界
- 不改四页主链跳转。
- 不碰插件链、服务链、控制台日志链。
- 不新增页面，只收口 Welcome -> ModuleSelection -> Management -> Dashboard 四页展示层。

## 10. 2026-04-16 第四轮人工验收反馈收口

本轮不改四页主链，不碰插件链，不碰控制台日志链，只处理真实运行截图中已被用户明确指出的三类视觉问题：

- WelcomePage
  - 整体布局保持不变，但主视觉内部排版需要重新收口。
  - logo、英文标题、中文标题、描述文案与主按钮需要形成更紧凑的连续信息组。
  - 额外纵向空间优先分配给品牌信息组本身，而不是继续制造内部空场。
- ModuleSelectionPage
  - 页面整体骨架保持不变，只修卡片内部排版。
  - `ANKLE` / 状态标签需要从“左右甩开”改为“左侧成组”。
  - 标题、描述、提示、按钮之间的节奏要更稳定，避免出现块内信息看着松散但按钮又偏小的情况。
- ManagementPage
  - 页面结构与流程保持不变，只回调纵向密度。
  - 概览卡、上下文条、搜索栏、表头和表格行高需要整体回弹，避免出现“空间很多但字和块都偏小”的观感。
- DashboardPage
  - 用户已明确表示当前观感没有问题，本轮不做主动修改。

本轮设计关键词：
> 保持骨架，重排内部节奏。

本轮收口优先级：
1. Welcome 主视觉内部信息组
2. ModuleSelection 卡片内部信息组
3. Management 块体与表格纵向密度
4. Dashboard 保持现状

## 11. 2026-04-16 模块页补充微调

基于最新人工验收截图，`ModuleSelectionPage` 再追加一轮只针对卡片内部排版的补充收口：

- 顶部 `ANKLE / 需排查` 与 `CONFIG / 辅助入口` 需要从“高条块”收回到“扁标签”比例。
- 两组标签字体需要继续放大，但纵向高度要明显降低。
- `踝关节手术工作流` 与 `系统设置与检查` 两个模块标题继续放大。
- 每张卡内部两行小字之间的垂直节奏继续收紧，其余结构保持不变。
