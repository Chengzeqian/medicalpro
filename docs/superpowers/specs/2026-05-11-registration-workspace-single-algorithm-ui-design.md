# 手术导航配准环节单算法科研界面设计

**日期：** 2026-05-11  
**范围：** `medicalpro` 手术导航工作区中的“03 配准”阶段  
**设计方向：** 围绕当前主链路算法 `ankle_two_stage_constrained` 重构配准页 UI，突出推荐采点、约束区精配准、融合导航空间和导航准入判断

## 1. 背景

当前配准页仍保留旧式分组结构：

- `2D-3D 配准`
- `点配准`
- `光学配准`

但项目中真正与导航主链路打通的能力并不是这三个并列流程，而是以下单链路：

1. 在配准 VTK 视图中选择 CT 源点
2. 采集或生成对应探针目标点
3. 执行地标点刚体粗配准
4. 基于目标区和约束区执行表面精配准
5. 生成 `fused navigation space`
6. 结合探针校准状态判断是否满足导航准入

当前代码中的真实算法事实：

- 默认算法由 `PointRegistrationExecutionOptions` 指定，`registrationMethodId` 默认值为 `ankle_two_stage_constrained`
- `PointRegistrationServiceImpl` 先执行 weighted rigid landmark registration，再根据 `registrationMethodId` 选择是否委托 `RegistrationCore` 做 ICP/GICP 表面精配准
- 配准结果已写入 `PointRegistrationResult`、`NavigationWorkspaceRegistrationState` 和 `AnkleRegistrationRecord`
- 导航阶段已经消费 `FRE`、`Target TRE`、`coverageScore`、变换矩阵和 fused navigation space 状态

因此，配准页应当从“多入口旧界面”收敛为“单算法科研配准工作台”，使界面表达与系统主功能完全一致。

## 2. 目标

1. 将配准页明确改造成当前默认算法 `ankle_two_stage_constrained` 的单链路工作台
2. 保留当前“在 3D 模型上点 CT 点，再采集对应探针点”的真实能力
3. 默认提供“按规划推荐顺序引导”的采点流程，同时保留自由采点能力
4. 清晰展示两阶段配准结构：粗配准、约束区精配准、融合导航空间
5. 将探针校准从配准页主操作中降级为只读状态，主入口保留在准备页
6. 让用户一眼能判断当前是否满足导航准入，而不是只看到零散按钮和误差文本

## 3. 非目标

- 不新增新的配准算法
- 不把 4 种已有算法做成主界面可切换实验页
- 不恢复 `2D-3D 配准` 作为当前工作区主入口
- 不把探针校准主流程重新迁回配准页
- 不修改底层配准数学实现、VTK 管线或 `RegistrationCore` 算法接口

## 4. 真实算法约束

### 4.1 当前主算法

配准页默认围绕 `ankle_two_stage_constrained` 组织界面。该算法在当前系统中的含义是：

1. 使用成对的 landmark points 做 weighted rigid registration，得到粗配准变换
2. 依据规划中的 target region 与 anatomical constraint regions 选取精配准关注区域
3. 将粗配准结果和点云委托给 `RegistrationCore` 执行 GPU GICP 风格的表面精配准
4. 产出最终患者空间变换、`FRE`、`Target TRE`、`coverageScore` 和 `fused navigation space`

### 4.2 当前 UI 必须体现的算法结果

配准页必须能够表达：

- 当前算法策略固定为“地标点粗配准 + 约束区精配准”
- 推荐采点顺序来自 planning 数据
- 目标区半径和约束区数量会影响精配准
- `Target TRE` 比通用 `FRE` 更能体现目标区导航质量
- `coverageScore` 反映采点是否覆盖到足够有效区域
- fused navigation space 是否生成直接影响导航是否可进入

### 4.3 当前 UI 不应继续暗示的内容

- 当前临床/主流程正在让用户自由切 `ICP / GICP / landmark only`
- `2D-3D 配准` 是当前导航链路里的有效主步骤
- 探针校准和患者空间配准是两个并列主阶段

## 5. 交互定位

### 5.1 页面角色

配准页定位为：

**患者空间融合建立页**

这不是一个“所有配准工具集合页”，而是一个围绕当前病例规划和当前导航算法，完成患者空间建立的科研化工作台。

### 5.2 用户主流程

新的默认流程为：

1. 查看配准策略与规划约束摘要
2. 按推荐顺序选择当前应采的 CT 点
3. 采集对应探针点
4. 检查点对完整度和覆盖进度
5. 触发计算配准
6. 查看粗配准、精配准和 fused navigation space 结果
7. 确认探针校准状态是否已满足导航准入

### 5.3 采点模式

保留两种模式：

- `推荐顺序引导`
- `自由采点`

其中主界面默认进入 `推荐顺序引导`，自由采点作为辅助模式保留，不作为默认视觉中心。

## 6. 页面结构

### 6.1 总体布局

保留当前大布局：

- 左侧：工作流轨道
- 中间：配准 VTK 主视图
- 右侧：科研控制与结果面板

但右侧内容从旧式三组控件重构为四段科研面板：

1. `配准策略`
2. `采点引导`
3. `点集进度`
4. `配准结果`

底部保留一个 `导航准入状态` 区域，用于只读显示探针校准与导航门禁状态。

### 6.2 中央主视图

中间区域继续保留大尺寸 VTK 配准视图，用于：

- 加载当前用于采点的骨模型
- 可视化 CT 点和探针点
- 突出当前推荐点位或选中点位
- 在配准完成后显示误差线和变换结果

主视图不再与大量操作按钮竞争视觉层级。

## 7. 右侧四个核心面板

### 7.1 配准策略面板

定位：只读说明当前病例和当前算法策略。

显示内容：

- 算法链：`地标点粗配准 -> 约束区精配准`
- 精配准内核：`GPU GICP`
- 目标：`生成 fused navigation space`
- target region 半径
- anatomical constraint region 数量
- 推荐采点顺序是否已加载

交互原则：

- 不提供算法切换按钮
- 不暴露 2D-3D 入口
- 不显示“多算法并列选择”

### 7.2 采点引导面板

定位：指导当前应该采哪个点，以及下一步该做什么。

默认模式：`推荐顺序引导`

显示内容：

- 当前建议点位名称
- 所属骨 / 区域
- 推荐原因
- 当前进度：`已完成 N / 计划 M`
- 当前模式切换：`推荐顺序引导 / 自由采点`

操作按钮：

- `添加 CT 点`
- `采集对应探针点`

行为要求：

- 用户在 VTK 视图点选后，先形成 CT 点
- 探针点采集按钮负责补齐当前点对
- 如果当前点对未完成，界面明确提示用户下一步是“补采探针点”而不是继续选下一个 CT 点

### 7.3 点集进度面板

定位：展示点对质量与可计算性。

顶部摘要：

- 完整点对数
- 最少要求：3 对
- 推荐范围：5-7 对
- 约束区覆盖情况

表格列建议：

- 序号
- 推荐点名
- CT 点
- 探针点
- 状态
- 点误差

状态值建议：

- `待选 CT`
- `待采探针`
- `已成对`
- `建议复采`

操作按钮：

- `删除选中点`
- `清空点集`

### 7.4 配准结果面板

定位：展示当前算法链的计算结果与导航价值。

必须显示：

- `FRE`
- `Target TRE`
- `覆盖率`
- `fused navigation space`
- `粗配准状态`
- `精配准状态`
- `平移 / 旋转摘要`

如果存在扩展指标，则显示为科研结果项：

- `refine_method`
- `constraint_refine_used`
- target region metrics
- planning constraint metrics

成功结论文案示例：

- `目标区已完成约束配准`
- `融合导航空间已生成`
- `当前结果可用于导航准入评估`

失败结论文案示例：

- `有效点对不足`
- `粗配准失败`
- `约束区精配准未收敛`
- `融合导航空间未生成`

## 8. 探针校准呈现

### 8.1 角色变化

探针校准主入口继续放在准备页，本页不再把它作为主要操作模块。

### 8.2 配准页中的呈现方式

配准页只读显示：

- 校准状态：已完成 / 未完成 / 进行中
- 当前采样进度
- 当前校准精度
- 如果未完成，提示：`请回准备页完成探针校准`

### 8.3 与导航准入的关系

导航准入区统一汇总：

- 患者空间配准是否完成
- fused navigation space 是否生成
- 探针校准是否完成
- 当前 confidence / gate reasons

这样用户能在配准页看到“为什么还不能进导航”，但不会把探针校准误解为本页的主任务。

## 9. 必须移除或弱化的旧结构

新的主界面应移除或显著弱化：

- `2D-3D 配准` 分组
- `光学配准` 作为并列主流程分组
- `计算` 这类过泛文案
- 只显示一个 `误差` 数值而不显示完整科研结果

保留但降级：

- 自由采点
- 旧表格基础能力
- 当前 `collect / delete / clear / compute` 底层槽函数

## 10. 文案规范

建议统一使用下列术语：

- `患者空间融合建立`
- `推荐采点顺序`
- `目标区`
- `约束区`
- `粗配准`
- `精配准`
- `fused navigation space`
- `导航准入`
- `校准状态`

避免继续使用：

- `2D-3D 配准`
- `光学配准` 作为本页主标题
- `计算`
- `误差：- mm` 这种信息量过低的显示

## 12. 实现策略

1. 先重构配准页右侧结构，删除旧三组并列思维
2. 将推荐采点引导、点对进度、结果矩阵拆成新的研究型面板
3. 复用现有 `PointRegistrationService`、`RegistrationWorkflow`、`NavigationWorkspaceApplicationService` 的真实数据
4. 不在 UI 层伪造算法状态，只展示真实 workflow state 和 result metrics
5. 将探针校准区域改成只读状态卡，不再作为本页主操作组

## 13. 验收标准

1. 页面不再出现 `2D-3D 配准` 作为主分组
2. 页面默认围绕 `ankle_two_stage_constrained` 单链路表达
3. 能看出“推荐采点顺序引导”是默认流程
4. 仍保留自由采点能力
5. 结果面板明确显示 `FRE`、`Target TRE`、`覆盖率`、`fused navigation space`
6. 探针校准在本页只作为只读状态出现
7. 用户能一眼判断当前是否满足导航准入
8. 界面风格与现有导航工作区深色科研风格一致

## 14. 成功判定

本轮成功的标志是：用户进入配准页后，不再看到旧式多配准模块堆叠，而是看到一个明确服务于当前导航算法的科研化配准工作台。用户可以沿推荐顺序完成采点、查看目标区与约束区相关指标、确认 fused navigation space 是否生成，并同步知道探针校准和导航准入是否满足。
