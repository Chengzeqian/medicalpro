# Welcome / ModuleSelection / Dashboard UI 技术落地方案

## 1. 目标

- 在不推翻现有 `Qt Widgets + .ui + NewPages` 架构的前提下，先把欢迎页、模块选择页、Dashboard 三页做成一套统一、稳定、可继续扩展的医疗工作站 UI。
- 保留欢迎页，不再要求登录。
- 保持 CTK 插件框架、现有页面跳转和服务调用不受影响。
- 让后续 UI 优化从“改样式”升级为“有组件、有令牌、有页面骨架”的持续工程。

## 2. 当前现状

### 2.1 已有基础

- `MainInterfaceWidget` 已经接入 `WelcomePageNew`、`ModuleSelectionPageNew`、`DashboardPageNew`。
- 页面流转已经满足当前业务要求：
  - Welcome -> ModuleSelection
  - ModuleSelection -> Management / SystemSettings
  - Dashboard -> Welcome / Navigation / Management
- 项目当前仍以 `Qt Widgets` 为主，不适合这一阶段直接整体切到 QML。

### 2.2 当前问题

- 三页样式各自为政，主要依赖页面级 `styleSheet`，缺少统一设计令牌。
- 视觉层级偏弱，页面“能用”，但不够像医疗导航工作站。
- 交互反馈较少，按钮、卡片、状态切换缺少明确节奏。
- `.ui` 和部分 `.cpp` 中存在中文乱码，说明字符串编码链路不稳定，这会直接影响 UI 文案质量。
- Dashboard 里数据密度开始上升，但信息分区还不够清晰。

## 3. 三种技术路线

### 路线 A：纯 Qt Widgets 轻量主题化

- 做法：继续使用现有 `.ui` 页面，补一层统一 QSS 主题和少量通用组件封装。
- 优点：风险最低，和当前代码最兼容，最快看到效果。
- 缺点：窗口框架、停靠布局、标题栏质感提升有限。

### 路线 B：Qt Widgets + 主题层 + 窗口增强库

- 做法：在路线 A 基础上，引入轻量 UI 增强库，分阶段升级。
- 推荐组合：
  - `Qt Advanced Stylesheets`：统一主题与控件皮肤
  - `QWindowKit`：窗口框架、标题栏、无边框体验
  - `KDDockWidgets`：后续导航/影像/工具面板的专业停靠布局
- 优点：最适合医疗工作站产品化，兼容当前 Widgets 架构。
- 缺点：需要一轮样式基础设施整理。

### 路线 C：局部引入 Qt Quick Controls

- 做法：欢迎页或 Dashboard 局部用 QML 重做视觉层。
- 优点：视觉上限最高，动画更自然。
- 缺点：项目会进入 Widgets/QML 混合栈，维护成本显著上升。

## 4. 推荐路线

选择路线 B，但分两期落地：

- 第一期：只用现有 `Qt Widgets` 完成三页视觉重构和组件抽象，不新增高风险依赖。
- 第二期：在主窗口层评估 `QWindowKit`，在导航和工作区层评估 `KDDockWidgets`。

这样做的原因很直接：

- 你现在最需要的是先把系统界面“站起来”，而不是把 UI 技术栈推翻。
- 三页是用户第一眼看到的地方，优先把信息层级、品牌感、交互反馈做对，收益最大。
- 当前插件框架、构建链、运行配置刚稳定下来，不适合马上做 QML 级别重构。

## 5. 统一 UI 基础层

### 5.1 设计令牌

建议先抽出一套统一令牌，后续三页全部使用：

- 颜色
  - 主背景：深蓝灰手术室基底
  - 强调色：医疗红 / 设备橙二选一
  - 信息色：成功、警告、异常、在线状态
- 字体
  - 标题：有识别度但稳重的中文黑体
  - 正文：清晰、密度适中的 UI 字体
- 间距
  - 8 / 12 / 16 / 24 / 32 为基础步进
- 圆角
  - 8 / 12 / 16
- 阴影
  - 卡片轻阴影
  - 关键 CTA 中阴影
- 动效
  - 页面进入淡入 + 上移
  - 卡片 hover 提升
  - 主按钮按下反馈

### 5.2 组件层

建议新增一层轻量 UI 组件，不重做框架，只补最常用的几个：

- `PageShell`
  - 统一页面外边距、标题区、状态区、底部操作区
- `HeroPanel`
  - 欢迎页顶部视觉区
- `ActionCard`
  - 模块卡片、功能入口卡片
- `InfoCard`
  - Dashboard 数据概览卡
- `SectionHeader`
  - 标题 + 描述 + 操作按钮
- `StatusBadge`
  - 在线、就绪、异常、未连接

### 5.3 文案与编码修复

在 UI 正式优化前，必须先做一轮中文编码清理：

- 把欢迎页、模块选择页、Dashboard 的 `.ui` 和相关 `.cpp` 字符串统一转为正确 UTF-8。
- 所有用户可见文本统一收口，避免继续散落在多个页面文件里。

这一步不是“顺手修”，而是 UI 落地前置条件。

## 6. 三页落地方案

### 6.1 WelcomePage

目标：从“启动页”升级为“产品入口页”。

建议结构：

- 左侧 / 中央 Hero 区
  - 系统名
  - 一句副标题
  - 当前系统状态摘要
- 底部操作区
  - `进入系统`
  - `退出系统`
- 背景层
  - 渐变 + 低对比几何网格或医学影像轮廓纹理

建议强化点：

- Logo 区不要只放图片，可加系统代号和版本信息。
- 欢迎页增加“运行环境状态摘要”，例如：
  - 插件框架：已初始化
  - 数据服务：已连接 / 未连接
  - 影像服务：已就绪 / 检查中
- 进入系统按钮做成主 CTA，退出按钮降级。

### 6.2 ModuleSelectionPage

目标：从“两个按钮的中转页”升级为“工作台入口页”。

建议结构：

- 顶部工具条
  - 当前用户或访客身份
  - 当前日期时间
  - 系统运行状态
  - 退出
- 中央主区
  - 2~4 张主模块卡片
  - 当前阶段先保留：
    - 踝关节手术
    - 系统设置
- 底部辅助区
  - 最近任务
  - 常见入口
  - 版本/运行环境说明

建议强化点：

- 模块卡片不只是“按钮 + 图标”，而是：
  - 模块名
  - 模块说明
  - 可用状态
  - 点击后的关键收益
- 每张卡片使用统一 `ActionCard`，支持 hover、focus、disabled 三种状态。
- 后续插件增多后，这一页可以自然扩展成模块门户，不需要再推翻。

### 6.3 DashboardPage

目标：从“患者列表 + 详情”升级为“病例工作台”。

建议结构：

- 顶部条
  - 返回管理
  - 页面标题
  - 当前患者状态
  - 刷新 / 退出
- 左侧窄栏
  - 患者搜索
  - 患者列表
  - 当前筛选状态
- 右侧主工作区
  - 第一行：概览卡
    - 基本信息
    - 诊断
    - 主治医生
    - DICOM 检查数
  - 第二行：病例详情 / 治疗摘要
  - 第三行：DICOM 检查卡片流
  - 底部：进入导航主按钮

建议强化点：

- 用 `InfoCard` 把患者核心信息拆开，避免全部堆成一块。
- DICOM 区域做成“检查时间轴 + 缩略卡片”，而不只是重复方块。
- `进入导航` 作为页面最强动作，需要视觉上明确收口。
- 后续如果引入 `KDDockWidgets`，Dashboard 可以平滑升级成可停靠工作区。

## 7. 推荐库结论

### 这一阶段最适合的库

- `Qt Advanced Stylesheets`
  - 作用：统一主题、控件外观
  - 用法：先做主题基建，不要求一次性覆盖全项目
- `QWindowKit`
  - 作用：主窗口边框、标题栏、系统按钮体验优化
  - 用法：第二阶段再接入，不阻塞三页首轮改版
- `KDDockWidgets`
  - 作用：专业级停靠布局
  - 用法：在 Navigation / Dashboard 工作区阶段引入最合适

### 可以关注但不建议现在就上

- `SARibbon`
  - 如果未来系统偏设备控制台、术中操作台，可考虑
  - 当前三页首轮优化不需要先引入
- `Qt Quick Controls`
  - 适合局部高视觉页面
  - 但当前不建议立刻把三页切到 QML

## 8. 实施顺序

### Phase 1：基础修复

- 固定运行配置和正确工作目录
- 清理三页可见文案乱码
- 抽出主题令牌和公共 QSS

### Phase 2：三页改版

- 重做 WelcomePage 视觉层级
- 重做 ModuleSelectionPage 卡片化入口
- 重做 Dashboard 信息分区和 CTA

### Phase 3：组件沉淀

- 抽 `ActionCard`、`InfoCard`、`SectionHeader`、`StatusBadge`
- 收口重复样式和状态颜色

### Phase 4：窗口与工作区增强

- 评估 `QWindowKit`
- 评估 `KDDockWidgets`

## 9. 验收标准

- 三页视觉语言统一，用户一眼能看出是同一套系统。
- 欢迎页保留且无需登录。
- 模块页不再只是过渡页，而是正式工作台入口。
- Dashboard 的信息密度提升，但不杂乱。
- 所有中文文案显示正确。
- 不破坏现有 CTK 服务加载、页面跳转和插件运行。

## 10. 下一步建议

下一轮直接进入可实施阶段，建议顺序如下：

1. 先做三页文案编码修复和主题令牌落地
2. 先改 WelcomePage，再改 ModuleSelectionPage，最后改 DashboardPage
3. 三页稳定后，再决定是否引入 `QWindowKit` / `KDDockWidgets`
